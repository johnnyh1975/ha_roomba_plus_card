# v2.0.3

Patch release covering everything since v2.0.0. No breaking changes, no config migration needed.

**Requires:** roomba_plus integration ≥ 2.8.6

---

## New feature: room area labels on the Map tab

Room boundary labels on the Map tab now show floor area when available, e.g. "Kitchen / 20.0 m²". The data comes from the `region_areas_m2` attribute on `select.*_smart_zone_select` (same entity as `region_icons`) — requires integration ≥ 2.9.1.

Degrades gracefully: if the attribute is missing (local-only setup, integration < 2.9.1, inactive floor, or EPHEMERAL robot) the label shows the room name only, as before. No configuration needed.

---

## Bug fixes

**"Rooms…" button appeared on EPHEMERAL robots (e.g. 980) and then failed**

EPHEMERAL robots have a `zone_select` entity with real room options, but the underlying `roomba_plus.clean_room` service throws a `ServiceValidationError` for any robot that isn't SMART-tier — making the button a promise it couldn't keep. The multi-select room picker (header button, chip list, Map tab tap-to-select) now requires `hasSmartZones` rather than just `hasZones`. EPHEMERAL robots' single-zone targeting model (select + a separate ZoneCleanButton) is a different interaction pattern that isn't yet implemented; the button is simply absent until it is.

**Mission result icons: three tiers instead of two**

Previously every result other than `completed` showed a red ✗ — including `stuck_and_resumed`, `error_battery`, and `cancelled_by_user`. These are missions that ended; the robot recovered or was stopped intentionally. Three tiers now:

| Icon | Tier | Results |
|---|---|---|
| ✓ | Success | `completed`, `stuck_and_resumed` |
| ⚠ | Caution — mission ended, with an incident | `cancelled`, `cancelled_by_user`, `error`, `error_battery` (and any other `error_*`), `unknown` |
| ✗ | Failure — never recovered or never ran | `stuck`, `stuck_and_abandoned`, `blocked_timeout` |

**Battery health bar was always gray**

The battery retention bar and coverage percentage bar used `<span>` elements for their track and fill, while the consumable bars (Filter, Brush) correctly used `<div>`. CSS `height: 100%` has no effect on inline elements, so the green fill span rendered with zero visible height. Changed to `<div>` — the bar now shows the correct green/amber/red fill.

**Battery health popover had no "Mark as replaced" button**

The Filter and Brush popovers both had a "Mark as replaced" button wired to their respective reset services. The Battery Health popover didn't, despite `roomba_plus.reset_battery` existing and working the same way. Added.

**Battery maintenance row in ⚙ tab showed no last-reset date**

The Wheel, Contact, and Bin maintenance rows in the ⚙ tab all showed "Reset X ago" / "Never recorded". Battery baseline only showed the service name. `sensor.*_battery_last_replaced` exists in the integration (same IA74-MAINT timestamp pattern) — now read and displayed consistently.

**Map tab showed History tab content**

The Map tab rendered "LAST 28 DAYS", "100% completion rate", and the Stats/lifetime footer — all of which belong to the History tab, not to a spatial coverage view. The Map tab now shows only: heatmap + legend + "Updated X ago".

**Map tab showed a Calendar/Coverage toggle that shouldn't be there**

Tapping "Calendar" inside the Map tab silently switched its content to the calendar heatmap while the tab bar still showed "Map" as active. The toggle is now suppressed in the Map tab and the standalone History tab — it only appears in the companion mode History tab, where no separate Map tab exists to hold the coverage view.

**WiFi sparkline showed "0% min" for almost every mission**

The `wifi_signal` array from the API is a 5-element count histogram (number of readings per signal-strength bucket), not a sequence of percentage values. The card was treating the counts as percentages directly — a count of 0 in a bucket read as "0% signal", which meant every mission with any empty bucket (nearly all of them) showed a near-zero minimum. Fixed using the same weighted-mean formula the integration's own `wifi_health` sensor uses. The label now reads "X% avg" instead of "X% min", which is the correct description for histogram data.

**v2.0 entities were missing from the render guard**

`relevantEntityIds()` decides whether to re-render when Home Assistant pushes a state update. Twelve v2.0 entities were never added to this list, so updates to `robot_health_score`, `mission_progress`, `wheel_last_cleaned`, `battery_last_replaced`, `carpet_boost_select`, `edge_clean`, `always_finish`, and several others would sit in the new state unrendered until some other tracked entity happened to change. All missing entities added.

**Health tab could be entirely empty for retention-only or coverage-only robots**

The early-return guard that skips rendering the Health tab when no content exists didn't account for `hasBatteryRetention` or `hasCoveragePct` — two sections computed independently of the consumable bars array. A robot with only battery retention data (no filter, no brush, no health score, no maintenance calendar) would see a blank Health tab. Fixed.

## Upgrade notes

No config changes needed. All `show_*` options from earlier versions continue to work.

If you have `mode: companion` set, the Map tab was already hidden — no change there.

If you were relying on the room picker appearing for an EPHEMERAL robot (980-series), it will no longer appear. This is intentional: the button was connected to a service call that would have failed anyway.
