# Roomba+ Card v3.0.1

> **Minimum:** integration **4.2** · Home Assistant **2025.5** (unchanged).

A small release: an option for maps with many rooms, card diagnostics that
say why something is missing, and a favourite that should never have been
there.

## Room labels on the map: name only, or none

With many rooms, a label of "name / area" on every room crowds the map.
New option **`map_room_labels`** — also in the visual editor as *Room
labels on the map*:

| Value | Shows |
|---|---|
| `full` (default) | icon, name and area, as before |
| `name` | icon and name |
| `none` | no labels; rooms stay tappable, and the room name appears on hover |

```yaml
type: custom:roomba-plus-card
entity: vacuum.your_roomba
map_room_labels: name
```

It applies to the room map and to the coverage view. The room area now also
follows `area_unit` (m² or ft², by default your Home Assistant unit system);
up to 3.0.0 the map always printed m².

Thanks to **BobR1** on the Home Assistant community forum for the request.

## Card diagnostics: why something is missing

**⚙ → Card diagnostics** now says, for an entity that is missing because
the integration creates it only for some robots, which robots those are —
"only with Smart Map robot and iRobot account" for the mission progress on a
980, for example. A missing row without such a note is a real gap worth
reporting. Role names and the summary follow your Home Assistant language;
the copied Markdown stays in English for issues.

## A favourite that is not one

A firmware-internal routine (`_mission_init_config_…`) showed up as a
favourite button on Classic robots. The iRobot app does not let anyone start
a routine name with an underscore; the card now leaves such entries out, as
the integration already did for Prime robots. Thanks to **@Geo26160** for
the screenshot.
