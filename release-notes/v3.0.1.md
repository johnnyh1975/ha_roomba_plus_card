# Roomba+ Card v3.0.1

> **Minimum:** integration **4.2** · Home Assistant **2025.5** (unchanged).

A small release: four fixes and wishes from GitHub issues, an option for
maps with many rooms, card diagnostics that say why something is missing,
and a favourite that should never have been there.

## Bin full and bin missing get their own alert (#33)

Up to 3.0.0 a full bin only showed while maintenance was due, and then as a
generic "Maintenance due". The card now shows its own alert in the Care tab —
**Bin full — empty to continue** or **Bin missing — put it back to
continue** — and badges the Care tab.

It reads the integration's bin sensors (`binary_sensor.<robot>_bin_full`,
`binary_sensor.<robot>_bin_present`) and falls back to the readiness sensor
(`bin_full`, `no_bin`) where those sensors are missing. A missing bin wins
over a full one. Readiness states that change by themselves during a mission
(saving the map, final docking …) still get no alert of their own; that
belongs to a later release.

Thanks to **@azrael-229** for the detailed report.

## Firmware badge only after a real update (#32)

The **⬆ FW** badge is meant for 24 hours after a firmware update. Up to 3.0.0
the card took that time from the version sensor's last change — which Home
Assistant resets on every restart, so the badge showed after each restart.
It now follows the integration's **Firmware updated** sensor
(`binary_sensor.<robot>_firmware_updated`, Classic robots), which is on for
24 hours after the robot reported a new version. Prime robots have no such
sensor and show no badge.

A long version string no longer pushes the badge past the card edge: it is
shortened with "…", and the full version is in the tooltip.

## Calendar weeks start on your first day of the week (#30)

The History calendar started every week on Monday. It now uses the first day
of the week from your Home Assistant profile. With *Use language setting*,
the card follows your language's convention as your browser knows it —
Sunday for US English, Monday for most others; a browser without that
information falls back the way Home Assistant does (Sunday for US English,
otherwise Monday). Day labels and the loading placeholder follow too.

## Fold the tabs away (#31)

Tap the open tab to fold the tab area away — the header and the tab bar
stay. Tap any tab to open it again. To start folded, use the new value
**`default_tab: none`**, also in the visual editor as *None — start
collapsed*:

```yaml
type: custom:roomba-plus-card
entity: vacuum.your_roomba
default_tab: none
```

A changed `default_tab` now applies in the editor preview right away. Alerts
stay reachable while folded: the tab badges keep showing them.

Thanks to **@djdelorie** for #30, #31 and #32.

## Room labels on the map: name only, or none

With many rooms, a label of "name / area" on every room crowds the map.
New option **`map_room_labels`** — also in the visual editor as *Room
labels on the map*:

| Value | Shows |
|---|---|
| `full` (default) | icon, name and area, as before |
| `name` | icon and name |
| `none` | no labels; rooms stay tappable, and the room name appears on hover |

```yaml
type: custom:roomba-plus-card
entity: vacuum.your_roomba
map_room_labels: name
```

It applies to the room map and to the coverage view. The room area now also
follows `area_unit` (m² or ft², by default your Home Assistant unit system);
up to 3.0.0 the map always printed m².

Thanks to **BobR1** on the Home Assistant community forum for the request.

## Card diagnostics: why something is missing

**⚙ → Card diagnostics** now says, for an entity that is missing because
the integration creates it only for some robots, which robots those are —
"only with Smart Map robot and iRobot account" for the mission progress on a
980, for example. A missing row without such a note is a real gap worth
reporting. Role names and the summary follow your Home Assistant language;
the copied Markdown stays in English for issues.

## A favourite that is not one

A firmware-internal routine (`_mission_init_config_…`) showed up as a
favourite button on Classic robots. The iRobot app does not let anyone start
a routine name with an underscore; the card now leaves such entries out, as
the integration already did for Prime robots. Thanks to **@Geo26160** for
the screenshot.
